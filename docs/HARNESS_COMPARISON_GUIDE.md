# Harness 적용 전후 비교 가이드

## 이 프로젝트에서 Harness란?

Harness는 MCP 도구 자체가 아니라 도구 호출을 둘러싸는 실행·검증 계층입니다.

```text
Harness 미적용
사용자 입력 → MCP 도구 → 결과

Harness 적용
사용자 입력
→ 필수 입력 사전검증
→ 도구 허용 목록 확인
→ MCP 도구 실행
→ 프로젝트별 결과 계약 검증
→ 실행 증거 JSON 생성
→ 검증된 결과
```

Harness를 꺼도 각 MCP Server가 가진 기본 검증은 남아 있습니다. 차이는 Harness가 여러 도구에 공통으로 적용하는 정책, 결과 품질 조건, 감사 증거가 없다는 점입니다.

## 수강생 시연 순서

1. Harness 토글을 `미적용`으로 바꿉니다.
2. 기본 입력으로 실행하고 결과의 노란색 `미검증` 배지를 확인합니다.
3. 비교 카드에서 사전검증·allowlist·출력검증·증거가 생략됐음을 설명합니다.
4. 토글을 `적용`으로 바꾸고 가능한 한 같은 입력으로 다시 실행합니다.
5. 초록색 `검증 완료` 배지와 `HARNESS-...` 증거 ID를 확인합니다.
6. 증거 JSON을 열어 toolName, inputKeys, outputKeys, 검증 문장, 지표와 시간을 확인합니다.
7. 회의록 입력을 비우는 등 오류를 만들어 Harness가 MCP 호출 전에 차단하는 장면을 보여줍니다.

검색과 메모리는 상태가 누적되는 데모이므로 완전히 같은 상태로 비교하려면 `실행 초기화` 후 같은 입력을 사용합니다.

## 프로젝트별 결과 계약

| 데모 | Harness가 추가로 확인하는 조건 |
|---|---|
| 회의록 | 모든 실행 항목에 담당자·업무·마감일 존재 |
| 견적서 | 합계가 공급가와 부가세의 합이며 0보다 큼 |
| 설계도 | 면적이 가로×세로와 같고 SVG 산출물 존재 |
| 대화형 검색 | citation 배열과 각 근거 ID·제목 존재 |
| 메모리 | 최신 기억에 시간·출처가 있고 타임라인으로 추적 가능 |

## 학습 포인트

- 좋은 결과가 한 번 나오는 것과 반복 실행을 신뢰할 수 있는 것은 다릅니다.
- Harness OFF는 빠른 탐색에 유용하지만 결과를 검증했다는 증거가 없습니다.
- Harness ON은 입력·도구·출력 계약을 한곳에서 관리하고 실행 증거를 남깁니다.
- Harness는 MCP Server의 자체 검증을 대체하지 않고 그 위에 공통 정책을 추가합니다.
