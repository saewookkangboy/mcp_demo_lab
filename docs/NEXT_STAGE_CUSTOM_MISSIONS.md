# Next Stage — 커스텀 개발 미션 3개

기본 5개 실습을 완료한 학습자가 기존 저장소를 복제하지 않고 직접 기능을 확장하는 단계입니다. 세 미션 모두 같은 개발 순서를 사용합니다.

```text
미션 선택
→ 기준 데모 실행
→ 실패 테스트 먼저 작성
→ MCP 도구 입출력 계약 확장
→ FE 결과 연결
→ Harness 적용 전후 비교
→ 전체 검증
→ Diff·화면·테스트 제출
```

## 시작 방법

1. Claude Code의 `Code → Local → Select folder` 또는 Codex의 `Open folder → Local`로 저장소를 엽니다.
2. `npm run verify`를 실행해 현재 기준 32개 테스트가 통과하는지 확인합니다.
3. 브라우저에서 `http://localhost:4173/next-stage.html`을 엽니다.
4. 미션 하나를 선택하고 `실습 프롬프트 복사`를 누릅니다.
5. Claude Code 또는 Codex에 붙여넣고 단계별 승인을 진행합니다.

기존 검증이 실패한 상태에서는 새 기능을 시작하지 않습니다. 학습자는 한 미션만 선택해도 되며, 팀 실습은 세 미션을 나누어 맡을 수 있습니다.

## 공통 개발 규칙

- 먼저 테스트를 추가하고 실패하는 이유를 확인합니다.
- 기존 MCP 도구 이름은 유지하고 필요한 입력과 결과 필드만 확장합니다.
- `src/server.js`의 결과가 `main.js`를 통해 FE에 표시되어야 합니다.
- Harness 미적용 결과와 적용 결과가 비교 카드에 각각 남아야 합니다.
- 정상값, 경계값, 오류값을 최소 한 번씩 실행합니다.
- 실제 고객·가격·건축·개인 데이터를 사용하지 않습니다.
- 최종 `npm run verify`에서 기존 테스트와 새 테스트가 모두 통과해야 합니다.

## MISSION-01 — 견적 할인 정책 추가

대상: `projects/02-instructor-quote`

### 완료 결과

- `calculate_quote`가 `customerType`을 입력받습니다.
- `standard`, `partner`만 허용합니다.
- `discountAmount`, `finalTotal`, `discountReason`을 반환합니다.
- FE에 할인 전 합계, 할인액, 최종 합계가 표시됩니다.
- Harness는 할인율 범위, 음수 금액, 최종 합계를 검증합니다.

### 필수 테스트

1. 일반 고객은 할인이 0원이다.
2. 파트너 고객은 정해진 할인율이 적용된다.
3. 알 수 없는 고객 유형은 도구 호출 전에 차단된다.

### 실패 시 확인

- 할인 후 금액이 0보다 작지 않은가?
- 세금과 할인 적용 순서가 테스트와 일치하는가?
- 화면 값과 MCP 반환 JSON이 같은가?

## MISSION-02 — 출입문과 안전 동선 설계

대상: `projects/03-beginner-blueprint`

### 완료 결과

- `generate_floor_plan`이 `doorSide`, `doorWidth`를 입력받습니다.
- 방향은 `north`, `south`, `east`, `west`만 허용합니다.
- SVG에 출입문과 피난 동선이 표시됩니다.
- `safetyWarnings`가 FE에 표시됩니다.
- Harness는 방향, 최소 문 폭, SVG와 경고의 일치를 검증합니다.

### 필수 테스트

1. 정상 출입문이 SVG에 표시된다.
2. 문 폭이 기준 미만이면 경고가 생긴다.
3. 알 수 없는 방향은 설계 전에 차단된다.

### 실패 시 확인

- 숫자가 아닌 문 폭이 조용히 변환되지 않는가?
- SVG에 입력 방향을 식별할 수 있는 값이 있는가?
- 교육용 개념도 안내가 유지되는가?

## MISSION-03 — 신뢰도 기반 메모리 충돌 해결

대상: `projects/05-advanced-memory`

### 완료 결과

- 사건에 `sourcePriority`가 추가됩니다.
- 우선순위는 `verified > user > inferred`입니다.
- 같은 `eventTime`이면 출처 우선순위로 현재 기억을 결정합니다.
- `winningEvent`, `rejectedEvents`, `resolutionReason`을 반환합니다.
- FE에는 선택된 기억과 탈락한 사건의 근거가 함께 표시됩니다.
- Harness는 무근거 덮어쓰기, 우선순위 누락, 세션 오염을 차단합니다.

### 필수 테스트

1. 같은 시각이면 검증된 출처가 우선한다.
2. 탈락 사건도 감사 타임라인에 남는다.
3. 새 세션은 이전 세션의 기억을 공유하지 않는다.

### 실패 시 확인

- 탈락 사건을 삭제해 추적성을 잃지 않았는가?
- 입력 배열 순서에 따라 결과가 달라지지 않는가?
- 두 번 연속 전체 테스트를 실행해도 결과가 같은가?

## Harness 비교 방법

각 미션에서 같은 입력을 사용해 다음 세 가지를 남깁니다.

| 실행 | 기대 상태 | 확인 내용 |
|---|---|---|
| Harness 미적용 | `PASS_THROUGH / UNVERIFIED` | 새 결과가 있으나 검증 증거가 없음 |
| Harness 적용 | `ALLOW / VERIFIED` | 새 계약과 증거 ID가 있음 |
| 계약 위반 | `BLOCK / REJECTED` | 잘못된 결과가 FE 전달 전에 차단됨 |
