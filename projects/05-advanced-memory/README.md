# 05. 데이터 기반 메모리 MCP — 고급

## 학습 목표

- 이벤트 로그와 현재 상태 저장소의 역할을 구분한다.
- 늦게 도착한 과거 데이터가 최신 상태를 덮지 않도록 충돌을 해결한다.
- 기억의 값뿐 아니라 시간·출처·전체 근거를 추적한다.
- 테스트마다 새 세션을 만들어 상태 오염을 방지한다.

## 실행과 예상 결과

`npm run dev` 후 `/projects/05-advanced-memory/`를 연다. 기본 데이터 3건을 저장하면 최신 상태는 `개발 중`, 담당자는 `민지`로 표시된다. 상태 카드에는 각 근거 ID가 남고 전체 타임라인에는 3건이 시간순으로 보인다.

한 번의 제출에서 `remember_events`, `recall_memory`, `inspect_timeline`이 연속 호출되는 기록을 확인한다. 실행 초기화는 화면 기록과 인메모리 상태를 함께 지운다.

Harness 비교에서는 최신 기억의 시간·출처와 타임라인 추적성 계약을 검증한다. 동일 사건의 재실행은 중복 근거로 쌓이지 않는다.

## 학습자 테스트

`node --test projects/05-advanced-memory/tests/app.test.js`

실습: 동일 시각에 서로 다른 값이 들어온 경우의 정책(먼저 도착/나중 도착/우선순위 출처)을 정하고 테스트를 먼저 추가한다. 그 뒤 `apply()`를 수정한다.

## 실패·검증 포인트

- 필드 누락: 어느 배열 원소의 어느 필드가 빠졌는지 오류에 나타나야 한다.
- 과거 사건: 로그에는 남지만 현재 기억에는 반영되지 않아야 한다.
- 격리: 새 세션의 기억은 비어 있어야 한다.
- 추적성: 모든 기억에 `at`, `source`가 있어야 한다.
- 주의: 메모리는 브라우저 새로고침 시 사라지는 인메모리 mock이다. 운영 환경에서는 DB, 인증, 보존·삭제 정책이 필요하다.
