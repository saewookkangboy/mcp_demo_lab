# 01. 회의록 작성 MCP — 강사 시연용

## 학습 목표

- MCP의 `tools/list`와 `tools/call` 개념을 5분 안에 설명한다.
- 비정형 회의 원문이 구조화된 FE 카드로 바뀌는 흐름을 관찰한다.
- 입력 검증이 도구 계층에 있어야 하는 이유를 확인한다.

## 실행과 예상 결과

전체 시연 화면에서 `회의록 작성`을 선택하고 `기본 입력 실행`을 누른다. 회의 제목, 참석자, 결정 사항 2개, 실행 항목 2개가 보인다.

결과 아래 MCP 실행 과정에서 `create_meeting_notes`의 입력·출력 JSON을 펼쳐 보고, 원문을 비워 빨간 오류 단계를 확인한다.

Harness 토글을 끄고 실행한 뒤 다시 켜서 실행한다. 미적용 결과에는 검증 증거가 없고, 적용 결과에는 실행 항목 완전성 검증과 증거 ID가 남아야 한다.

## 학습자 테스트

`node --test projects/01-instructor-meeting-notes/tests/app.test.js`

관찰할 파일: `src/server.js`는 MCP 도구, `main.js`는 Client 호출과 화면 출력을 담당한다. 테스트의 참석자 이름을 바꿔 정규식 추출 결과가 달라지는지 확인한다.

## 실패·검증 포인트

- 빈 원문: `필수 입력 누락: transcript` 오류가 나야 한다.
- 결과 카드: 모든 실행 항목에 담당자·업무·마감일이 있어야 한다.
- 주의: 요약 결과는 고정된 mock이며 실제 AI 요약 품질을 평가하는 데모가 아니다.
